# ssh-auto

`ssh-auto` — терминальный каталог SSH-подключений для Linux. Он показывает найденные подключения из истории команд и `~/.ssh/config`, позволяет сохранять свои профили и запускает выбранный хост через установленный в системе `ssh`. Сам сервер и ключи программа не создаёт.

## Установка и запуск

Нужны Python 3.10+, системный OpenSSH (`ssh -V`) и терминал для интерактивного интерфейса. Из корня проекта:

```bash
python3 -m venv .venv
.venv/bin/pip install .
.venv/bin/ssh-auto
```

Если окружение уже установлено, достаточно `.venv/bin/ssh-auto`. Необязательно: `pipx install .` позволяет запускать `ssh-auto` из PATH после настройки PATH для pipx.

## Первое подключение

1. При запуске откройте вкладку **«Найденные»** клавишей `Tab` или кнопкой. Здесь находятся простые SSH-команды из истории Bash, Zsh, Fish и конкретные `Host`-алиасы из `~/.ssh/config`. Если записей нет, добавьте профиль вручную клавишей `a`.
2. Выберите строку стрелками в таблице. `Enter` запускает системный `ssh` с выбранными destination и опциями; во время подключения терминал передаётся SSH, после его завершения интерфейс возвращается. Для алиасов из конфига действуют настройки самого SSH.
3. Чтобы сохранить найденную строку, на вкладке **«Найденные»** выберите её и нажмите `s`. Проверьте поля и нажмите **«Сохранить»**. Запись появится во вкладке **«Сохранённые»** и перестанет дублироваться в найденных при совпадении destination и опций.

Для ручного добавления нажмите `a` и заполните форму:

| Поле | Что вводить | Пример |
| --- | --- | --- |
| Имя | Удобное уникальное название профиля | `Рабочий сервер` |
| Destination | Один адрес или SSH-алиас; можно указать пользователя | `admin@example.org` |
| SSH options | Только параметры `ssh`, без самой команды и без destination; можно оставить пустым | `-p 2222 -i ~/.ssh/id_ed25519` |

Например, после сохранения профиля с destination `admin@example.org` и options `-p 2222 -i ~/.ssh/id_ed25519` запуск эквивалентен `ssh -p 2222 -i ~/.ssh/id_ed25519 admin@example.org`. Путь к ключу записывается в каталог, но содержимое ключа не копируется.

## Управление

| Действие | Клавиша или кнопка |
| --- | --- |
| Выбрать вкладку «Сохранённые» / «Найденные» | `Tab` или соответствующая кнопка |
| Добавить профиль | `a` |
| Сохранить выделенный найденный хост | `s` на вкладке «Найденные» |
| Изменить выделенный профиль | `e` на вкладке «Сохранённые» |
| Удалить выделенный профиль | `d` на вкладке «Сохранённые», затем подтверждение |
| Подключиться к выделенной строке | `Enter` в таблице |
| Найти запись | `/` или клик по полю поиска; ввод фильтрует текущую вкладку, `Enter` или `Escape` возвращает к таблице |
| Перечитать каталог и источники | `r` |
| Открыть справку / выйти | `?` / `q` |

Фильтр ищет по имени, адресу и опциям (а для найденных записей — также по источнику и числу использований); если запись пропала после поиска, очистите строку поиска. Изменение или удаление профиля не меняет историю shell и `~/.ssh/config`.

## Где хранятся данные

Профили записываются в `${XDG_CONFIG_HOME:-~/.config}/ssh-auto/profiles.yaml`, рядом создаётся `profiles.yaml.lock`. Каталог имеет права `0700`, YAML и lock-файл — `0600`. Имена профилей, destination и опции, в том числе пути к ключам и сведения о хостах, могут быть чувствительными: не публикуйте этот файл. Программа не сохраняет содержимое ключей, пароли, passphrase или живые SSH-сессии. Публичный SSH-ключ сам по себе не является секретом, приватный — является.

Истории Bash, Zsh и Fish и SSH config читаются при запуске и по `r`. Из истории импортируются только простые однострочные интерактивные команды `ssh` с одним destination; удалённые команды, продолжения строк, shell-выражения, `sshpass` и диагностические режимы не импортируются. Опции `-o ProxyCommand`, `LocalCommand`, `KnownHostsCommand`, `RemoteCommand` и обе формы `-F` запрещены при вводе и чтении каталога. При этом штатный `~/.ssh/config`, включая `Include`, не санитизируется: его `ProxyCommand` и `Match exec` могут запускать локальные команды. Подключайтесь только к доверенным алиасам.

Если приложение сообщает об ошибке YAML-каталога, исправьте файл вручную и нажмите `r`: до успешного перечитывания изменение профилей заблокировано. При сообщении о конфликте сохранения перечитайте каталог клавишей `r` перед повторной попыткой. Ошибки `Include` отображаются в предупреждениях; проверьте соответствующий файл конфига.

`.gitignore` снижает риск случайного добавления локальных файлов в этот проект, но не удаляет уже отслеживаемые или опубликованные данные. Перед публикацией проверьте индекс (`git diff --cached --name-only`) и историю используемого репозитория; раскрытые секреты нужно отозвать или сменить.
